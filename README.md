# AMB82-MINI 鳥類視覺與雙秤監控系統

目前版本：`0.15.0-robust-weight`；分支：`phase2/dual-weight-monitoring`。

目前提供鳥類追蹤與分群、每日到訪與群組相簿、雙 HX711 即時重量及獨立校正。使用方式以文末 v0.13.0（分群門檻）及 v0.14.0（雙秤整合）為準；本階段僅監控，不含補料、馬達或水泵控制。

整合韌體已編譯，重量、通訊、網頁與既有視覺回歸測試通過。尚未燒錄及完成雙秤實機驗證，軟體測試不代表實際秤重精度。

以下早期視覺設計與歷次版本說明保留作為演進紀錄；現行參數與功能以最新版本段落為準。

## 流程

F37 影像 → AMB82 YOLO 鳥類框 → 多目標追蹤 → 確認到訪 → 框內取樣與外觀分群 → UART 回傳統計 → localhost 顯示。

影像另由 OTG 的 USB UVC 傳至瀏覽器。沒有目標時等待；短暫漏偵保留追蹤，逾時結束到訪。通訊資料過期時介面隱藏舊框並提示，避免把舊資訊當成目前狀態。

## 計數與分群定義

- 最多同時追蹤 8 個目標，以框的重疊、中心距離與面積比例進行一對一配對。
- 連續 3 次偵測配對後確認到訪；持續停留 5 分鐘不因停留時間自動新增計數。
- 超過 3 秒未再配對即結束追蹤；再次出現會算新到訪。這是「到訪次數」，不是不重複個體數；遮擋、交錯與長時間漏偵仍可能造成重複計數。
- 使用鳥框內 RGB 取樣，計算 32 維顏色與紋理直方圖；不另載入分類神經網路。框小於 16×16 像素不取特徵。
- 偵測門檻為 0.25；外觀採樣需分數至少 0.40，重疊框會跳過採樣。每 500 毫秒至多一次，最多累積 5 份，至少 3 份有效樣本才分群。
- 外觀距離門檻為 0.22，最多 16 群；容量已滿且不符合既有群時保留未分群。參數仍需依實機資料調整。
- 每群顯示 8×8 RGB 代表縮圖，並非完整裁切照片。外觀相似不等於同種，也不能證明是同一隻鳥；光照、背景及姿勢可能影響結果。

## 每日統計與保存

電腦透過 TIME 指令定期校時；以台灣時間 UTC+8 的 08:00（含）到 17:00（不含）計算當日新到訪。未校時不計當日數量；08:00 前已存在的追蹤不當作時段內新到訪。跨日清除當日群組與計數。

開發板以 RAM 保存追蹤與群組，重開機會重設。電腦在 records/ 保存 JSONL 事件、每分鐘快照、跨日與關閉快照；電腦未連線期間的完整事件不會補傳。沒有跨重啟個體辨識，也不會從電腦紀錄還原開發板群組。

## 環境與操作

硬體為 AMB82-MINI、F37 相機、UART USB 與 OTG USB 資料線。使用 Windows PowerShell、Chrome/Edge、Arduino CLI 與 AmebaPro2 SDK 4.1.0。Build.ps1 會尋找本專案或相鄰「物聯網作業一」的 .tools；若缺少工具先執行 Setup.ps1。

自訓練模型放在專案根目錄 birds_2@yolov7-tiny.nb；模型未納入 Git。也可透過 Build.ps1 的 -ModelPath 指定檔案。此版使用 Flash NN 模型，不需 SD 卡模型或 Wi-Fi。

僅編譯：

    powershell -ExecutionPolicy Bypass -File .\Build.ps1

關閉會占用 UART 的程式，讓板子進入燒錄模式後執行（COM4 請依裝置管理員調整）：

    powershell -ExecutionPolicy Bypass -File .\Build.ps1 -Upload -Port COM4

必須透過這個腳本準備及上傳主韌體與 NN 模型，避免直接呼叫廠商工具而使用舊映像。完成後重置開發板，UART 保持連接以收取資料，OTG 接電腦以傳輸影像，再執行：

    powershell -ExecutionPolicy Bypass -File .\Start-Demo.ps1 -Port COM4

開啟 http://localhost:8080，允許相機權限，選擇開發板 USB 攝影機並啟動。關閉其他占用相機的程式。介面顯示框、追蹤 ID、停留時間、當日到訪與外觀群組；串列逾 3 秒無新狀態會顯示過期。

純介面模擬：

    powershell -ExecutionPolicy Bypass -File .\Start-Demo.ps1 -Simulate

模擬模式不能驗證開發板推論、真實特徵或分群效果。

## 驗證與後續實驗

可重跑的軟體測試（核心測試使用本機 VS 2022 Build Tools，介面測試使用 Chrome）：

    powershell -ExecutionPolicy Bypass -File .\tests\Run-VisualTests.ps1
    powershell -ExecutionPolicy Bypass -File .\tests\Test-VisualBridge.ps1
    powershell -ExecutionPolicy Bypass -File .\tests\Test-VisualDashboard.ps1

已覆蓋五分鐘連續停留、短暫漏偵、逾時新到訪、兩目標配對、跨日與時段邊界、特徵有效性及群組容量；另測試分段串列訊息、重開機紀錄、網頁多框、縮圖與過期顯示。編譯產物雜湊及驗證範圍見 experiments/vision/release-validation.json。

實機驗收待辦：

1. 確認 USB 影像、鳥框及 UART 統計同步，檢查 rgbFailures 是否增加、代表縮圖顏色是否正確；SDK RGB888 planar 格式與回呼生命週期仍需實機確認。
2. 單一目標停留 5 分鐘，預期僅新增一次到訪；短暫消失少於 3 秒應維持 ID，超過 3 秒後重現應新增到訪。
3. 兩目標同時出現、交錯、遮擋，記錄 ID 切換與漏計／重計，評估目前追蹤限制。
4. 相同及不同鳥類影像各重複測試，人工比較群組；不要把外觀群組直接標成物種。
5. 測試停止／重啟 USB 攝影機、拔除通訊、重置，以及 08:00／17:00 邊界，記錄恢復情形與統計限制。
6. 量測實際更新延遲及長時間穩定性，再決定是否調整門檻與記憶體容量。

## BBox 顯示門檻

網頁攝影機下方提供 25%～100% 信心分數滑桿，預設 25%。分數大於或等於設定值才顯示框；設定即時生效並保存在該瀏覽器。這只過濾網頁框，板端到訪計數及外觀分群不受影響。板端原始偵測門檻仍為 25%，不會回傳更低分數的目標。本次網頁修改不需重新燒錄。

## 0.3.1 校時清除修正（2026-10-19）

實機紀錄顯示同一天、開機時間持續增加時，群組曾由 8 群降為 0 群。根因為 TIME 校時後處理較舊的佇列影格，無號毫秒差值溢位，造成日期跳動而清除每日群組。已改為可處理稍早影格的有號時間差，並禁止較舊影格讓每日狀態倒退。

新增回歸測試先重現失敗，再確認修正後通過；涵蓋校時前影格、millis 環繞與午夜延遲影格。核心及橋接測試、韌體編譯通過。此修正需重新燒錄；實機長時間驗證待完成。先前已被清除的板端群組不會自動復原，電腦 records 中既有快照仍保留。

## 0.4.0 群組管理與並排監控

桌面寬度大於 850px 時，左側為鏡頭、右側為可獨立捲動的分群清單；較窄畫面改為上下排列。狀態與手動補充操作移至下方。

原本縮圖只有 8×8 RGB，因此放大很模糊。現在瀏覽器優先依板端回傳的鳥框，從 USB 即時影像裁切最長邊 192px 的預覽，不放大原始小框；以分數及框面積選擇較好的候選。這是非同步的顯示用預覽，可能受 UVC 與偵測延遲影響，不是精確同步的推論影格。板端 32 維外觀分群算法不變。沒有開啟攝影機、群組沒有新的可見目標或裁切太小時，仍顯示 8×8 色彩圖。裁切只存在瀏覽器記憶體，重新整理後需重新取得。

每張群組卡片提供「刪除此群」。確認後由電腦送出 DELETE_GROUP 日期 群組代號，板端確認才顯示成功。刪除整群會：
- 扣除該群的當日與本次開機到訪次數。
- 清除群組平均特徵與代表圖。
- 忽略該群仍在場的追蹤，直到消失超過 3 秒。
- 保留電腦端既有事件紀錄，另記錄刪除請求與回覆。

每次建立群組使用新的代號，避免重複刪除或過期請求誤刪重用的位置。換日、斷線、資料過期、舊韌體及回覆逾時均提供提示。這不是模型訓練，也不是永久黑名單；物件離開後再次出現仍可能形成群組。整群可能混有正確鳥類到訪，請先檢查再刪除。

韌體已編譯；核心刪除／扣數／在場忽略／重用防護、串列回覆、瀏覽器裁切／刪除回饋／左右版面及未連線 HTTP 拒絕測試通過。新版需重新燒錄並重啟 Start-Demo.ps1；實機刪除與預覽品質仍待驗證。舊韌體的刪除按鈕會停用。序列協定 version 保持 0.3.0 相容，使用 deleteGroups 能力欄位判斷功能。

版本標籤：v0.4.0-vision-preview。

## 0.5.0 分群品質修正（取代舊版門檻與網頁裁切行為）

1. 共用板端門檻：預設 60%，可設 25%～100%。滑桿調整後按「套用至開發板」，收到板端確認才生效；頁面會顯示板端目前值及尚未套用狀態。低於門檻的結果不參與新的配對、到訪確認與分群採樣。既有追蹤最多保留 3 秒以容忍漏偵。調整門檻時，未分群的累積樣本重設；已成立的歷史群組不追溯刪除。重開機恢復預設 60%，不會自動套用舊瀏覽器設定。

2. 減少外觀拆群：至少收集 5 份有效樣本，每份間隔至少 500ms。特徵只取框內中央 80% 的寬高，降低邊緣背景影響；色相使用循環相鄰分箱的平滑權重，飽和度也使用連續權重。實驗距離門檻由 0.22 改為 0.28。這些調整可能減少姿勢／光照引起的拆群，但也增加不同鳥混群的可能；不是鳥種分類，準確度需實際對照確認。

3. 同影格代表圖：移除瀏覽器以延遲框裁切當下 UVC 影像的方式。由板端在同一次推論回呼中，從該次輸入 RGB 影格擷取完整鳥框的 24×24 RGB 圖，採用分群取樣中最高分的代表圖。特徵則使用上述中央區域。24×24 仍是低解析度縮圖，不是高清照片；鳥本身太小或模型誤偵背景時，仍可能得到不理想的圖，但不再用「鳥離開後的另張畫面」補裁切。

4. 傳輸與保存：每秒輪流傳一群代表圖，最多 16 群約需 16 秒補齊；主狀態不重複夾帶所有圖片。電腦依日期與群組唯一代號快取，刪群、換日或重開機會排除舊快取。未收到圖片顯示等待，不自行截背景補圖。代表圖取得不依賴瀏覽器開相機。底層序列協定 version 維持 0.3.0 相容，能力由 confidenceControl / sameFrameThumbs 欄位表示。

驗證：低分不新增計數或分群、門檻等號邊界、調高門檻清除未分群樣本、適度外觀變化歸同群、同影格圖快取／刪除／換包、鳥離開後保留代表圖、板端門檻確認及既有刪群／校時回歸測試通過；韌體編譯通過。回呼堆疊用量降為 120 bytes，extractInto 為 360 bytes（不含呼叫鏈其他函式）。本版尚未燒錄；實機分群準確率、背景誤偵與長時間穩定性待驗證。

建議實測：同一鳥圖改變位置與角度至少 10 次，記錄拆群數；再加入另一鳥種，記錄混群數；調高門檻確認低分物件不再累積；快速移走鳥圖，確認保存的代表圖沒有換成移走後的背景。刪除舊誤判群組後再開始新一輪比較。

版本標籤：v0.5.0-vision-preview。

## 0.5.1 開機校時與分群資格修正（2026-10-21）

發現初次 TIME 可能在開發板尚未就緒時送出，舊服務要等下一分鐘才再次校時。期間建立的追蹤永久失去當日分群資格，即使後續已校時仍顯示未分群。

修正：收到 READY 立即校時；有效回傳仍顯示未校時時，每至少 2 秒重試。校時前建立的追蹤使用 awaitingClock 標記，在校時完成後的下一次有效偵測更新，依當下時間判斷是否可納入當日統計。已確認的到訪只補計當日數，不重複增加開機累計；已離開、統計時段外、先前已校時且於 08:00 前出現的目標，不會因此錯加。

網頁新增分群原因：等待校時、統計時段外、校時後等待有效偵測、本次到訪不在統計範圍、容量已滿、信心分數不足、有效樣本不足。小框或重疊仍會跳過特徵取樣，信心門檻不降低。

核心／串列橋接／瀏覽器回歸測試與韌體編譯通過；新增校時前目標恢復資格、不重複計數、已離開不計數、時段外不分群測試。此版尚未燒錄，實際效果待驗證。版本標籤 v0.5.1-vision-preview。

## 下一階段提案：每日到訪檔案與人工分群（尚未實作）

### 儲存方式

建議讓 AMB82 保持推論、追蹤及外觀建議分群，電腦接收程式負責 SQLite 資料庫與獨立影像檔。瀏覽器查詢資料庫並顯示日期、時間線、圖卡及人工操作。資料保存在本機，可備份資料庫與影像資料夾；不依賴開著網頁來保存。

### 一筆資料代表一次到訪

每筆 visit 記錄 device_id、board_boot_id、track_id（聯合唯一鍵）、first_seen、confirmed_at、last_seen、end_reason、最高信心分數、使用門檻、auto_group_id、manual_group_id、review_status、image_path、image_capture_time、image_missing_reason。UTC 保存時間，畫面及每日統計轉為 Asia/Taipei。未校時時保存板端毫秒與接收時間，避免把接收時間假裝成精確拍攝時間。

board_boot_id 必須由韌體在開機時產生並重複回傳；不能用目前橋接程式每次啟動新建的 visionSession 當永久鍵，否則重連可能重複計數。START 用唯一鍵新增或更新；END 補結束時間。開機／斷線時未完成的到訪標記「結束時間不確定」，不猜精確離開時間。忽略重複事件，重連不新增同一筆到訪。

### 每次到訪自己的影像

目前只保存「群組」代表圖，不能當成每一次到訪的照片。需新增 VISIT_IMAGE 協定，把影像綁定到 board_boot_id、track_id 及推論影格序號。取該次到訪有效樣本中最高品質的一張；來源仍是同一推論影格，不能用延遲 bbox 裁切目前 UVC 畫面。

先保存板端已有的低解析度同步圖，之後再評估 64×64 或 128×128 JPEG 的編碼與傳輸成本。目前 UART 115200 不是適合連續傳高清照片的通道，提升解析度前應量測傳輸延遲與推論影響。圖片以到訪唯一鍵命名、先寫暫存再完成，資料庫只引用寫入成功的檔案；沒有圖就顯示原因，不以背景或其他到訪圖補上。

電腦離線期間若要求零遺失，需要另加開發板 SD 卡緩存、序號及確認後補傳機制；目前 RAM-only 韌體無法保證離線完整保存。第一版明確標示連線中斷區段及缺圖筆數。

### 人工整理

在「當日到訪」圖卡勾選一筆或多筆，可移至既有人工群組、建立新群、合併群組，或拆出成另一群。人工群組使用持久 ID 與可修改名稱，不能沿用每日重設的板端群號。原始 auto_group_id 保留，人工修正另存；不直接訓練或修改模型。

**UVC 與推論為不同影像串流，這是時間及內容近似配對，不是硬體同步，也不保證確為同一隻鳥或同一影格。** 相似背景或相似鳥仍可能通過，應人工確認。不同裁切比例、快速移動、網頁延遲、光線變化也可能讓有效照片被拒絕。無法配對、畫面暫停／背景、鳥框太小、未開瀏覽器或傳輸太晚時，只保留板端小圖並在歷史頁標示；不使用事件發生後任意截圖補缺。

更佳樣本可能替換代表照片的資料庫引用；舊 JPEG 檔暫不自動刪除，避免與備份競爭，長期使用需留意磁碟空間。資料庫備份及查詢 ZIP 只包含目前引用的影像。若未來需要全天無瀏覽器保存或精準影格同步，仍需改成電腦常駐攝影服務或板端 JPEG／SD 儲存。

### v0.13.0 - 分群相似度與合併門檻

即時監控增加獨立的「分群合併門檻」滑桿（0–100%，預設 76%）。按下套用後，主機送出 `SIMILARITY n`，收到板端確認才顯示成功。舊韌體會停用此按鈕，需重新燒錄。門檻只影響後續完成樣本收集的分群；不回溯更改既有群或歷史紀錄，板子重啟後恢復 76%。

保留自動建群：通過門檻才併入既有群；沒有通過的群則建立新群；16 個群組額度已滿時保留未分群。第一隻鳥沒有群可比較，顯示「無既有群可比對」。未滿 5 個有效樣本、未校時等情況顯示原因，不顯示虛構的 0%。歷史舊紀錄沒有回傳分數時顯示「舊紀錄未提供」。

分數是外觀相似度指標，不是鳥種分類機率。維持原本特徵及三個限制，將其正規化為共同分數：

`S = 100 × (1 − clamp(max(d_mean, d_anchor × 0.24/0.26, d_region × 0.24/0.32), 0, 1))`

預設 76% 對應原本距離上限 0.24／0.26／0.32，門檻邊界採「大於等於」；合格群中仍選平均距離最小者。未通過時保留分數最高的候選群資訊，顯示與門檻相差多少「百分點」。例如分數 70%、門檻 76%，差 6 個百分點。這與「鳥類偵測最低信心分數」獨立，後者控制是否接受偵測及累積樣本。

新版 VISIT/track 封包的 grouping 包含 score（無比對則 null）、threshold、samples、eligible、decision、candidate、candidate_generation、candidate_day。資料庫保存比對當時的快照，因此調整滑桿不會覆蓋舊紀錄的判斷依據。主機只展示與保存，外觀特徵及分群仍在 AMB82 上計算。


### v0.14.0 - 視覺與雙 HX711 重量監控

以 `amb82_dual_hx711.ino` 為來源，拆成 `WeightCore.h`（可單獨測試的校正與穩定狀態機）及 `WeightRuntime.h`（GPIO、指令、封包），併入唯一的 `BirdFeederDemo.ino` 主迴圈。原始範例保留不修改。沒有馬達、水泵或補料操作，網頁與主機的 FEED/SKIP 控制已移除。影像、鳥類分群、到訪資料及相簿功能保留。

接線：1 號飼料秤 DT=D1/PF6、SCK=D2/PF7；2 號水秤 DT=D3/PF8、SCK=D4/PF11。兩組各使用一個 HX711 與荷重元，模組依原範例使用 3.3V 與共同 GND；這些是板上腳位標示，不是接頭的物理第幾腳。軟體腳位已對照本機 SDK 4.1.0。實際模組接線、荷重元額定容量及相機並行時序仍須現場確認。

操作：

1. 接好兩秤與空容器，啟動網站。移開畫面中的鳥類／鳥類測試圖片；板端視覺須正常運作，沒有偵測到鳥後先等待 3 秒。
2. 展開某一秤的「校正與歸零」，按「① 設定空載零點」並確認空容器，等待板端回報完成。
3. 放上額定容量內的已知砝碼，輸入克數，按「② 已知重量校正」。顯示「已接受」只代表開始取樣，必須等「板端已完成」。取樣先等待 1 秒、丟棄 4 筆，再平均 20 筆；整合版逾時上限 12 秒，取樣速度取決於 HX711 與主迴圈排程。
4. 移除砝碼確認回零，再放回砝碼驗證重量。兩秤互相獨立，可分別進行校正；一秤失敗不會清除另一秤係數。
5. 已校正且空容器穩定時可用「空容器歸零」，只改零點。鳥離開或碰撞後用「重新量測」，只清除濾波與舊穩定值，不改零點或換算係數。
6. 板子每次重啟都需重新校正，沒有自動歸零，也不會把目前飼料或水直接當成零點。

正常重量採 5 筆平均、每 0.5 秒回傳。初版穩定判斷採 3 秒觀察窗、原始窗口與平均值範圍不超過 2g；空載校正採 1000 ADC counts 的峰對峰上限。兩者為實驗初值，需以真實空載雜訊和荷重元測試調整 `WeightCore.h`，不是量測精度保證。未校正、無回應、資料過期或 ADC 飽和時即時重量為 null／「—」，不顯示成 0。穩定值可保留但會標示年齡與「保留值，非目前可信重量」。

尚未設定秤台 ROI，因此採保守策略：畫面任何受接受的鳥類追蹤都會暫停兩秤穩定值更新。鳥消失後先等待 3 秒，再重新累積重量穩定窗；視覺資料過期不視為無鳥。校正進行中遇鳥或視覺失效會中止，保留操作前係數。這是避免誤用干擾重量，不是把鳥重數學扣除；模型漏偵仍可能誤把靜止鳥當穩定重量，需機構隔離與實測。

通訊：`WEIGHT <32位request_id> <1|2> ZERO|MASS|TARE|REMEASURE|CANCEL [克數]`；回覆 `@WEIGHT_ACK`，分 ACCEPTED／COMPLETE／FAILED／REJECTED。`@WEIGHT` 包含 boot、seq、兩秤狀態、校正旗標、即時／穩定重量、取樣進度及最後操作結果。網頁送出時攜帶開機識別碼，主機拒絕過期連線；相同最近指令識別碼不重做校正。未知結果不自動重送。主機每 5 秒保存重量封包、另保存操作與回覆到既有 records 日誌，本版未增加重量歷史圖表。

驗證命令：`tests/Run-WeightTests.ps1`、`tests/Test-WeightBridge.ps1`、`tests/Test-WeightDashboard.ps1`；並執行視覺與歷史 HTTP 回歸測試及 `Build.ps1`。軟體測試、編譯與實機驗證狀態請見 `experiments/phase2/dual-weight-validation-20261028.json`。本版需燒錄後才可使用雙秤功能。


### v0.15.0 — 20% 偵測與重量防護（2026-10-30）

本節取代前文舊預設與重量取樣規則。偵測底層最低值、板端預設、網頁範圍與主機檢查統一為 20–100%，預設 20%；分群合併門檻維持 76%。板端收到設定才算套用成功，歷史分群不回溯。較低偵測門檻可能增加誤判及重量的鳥類干擾等待。

重量改採最近 5 筆中位數，穩定檢查使用去掉最高／最低各一筆後的範圍；偶發單筆跳值不直接拉動顯示。相對上次穩定值的變動超過 max(10 g, 上次重量絕對值的 10%, 空載雜訊換算克數的 6 倍)，顯示「重量變動確認中」，即時值為空，舊穩定值標示為保留值。新重量連續穩定 5 秒才接受；一般變動仍需 3 秒穩定窗。這些是實驗初值，不是精度保證。持續穩定的電子或機構偏移仍可能被接受，不能靠軟體判定一定是真實重量。

校正等待上限從 12 秒改成 30 秒。捨棄開始階段後，每至少 100 ms 收一筆，使用滾動 20 筆；去掉最高／最低各一筆再算平均與範圍，不穩就等下一個窗口。空載容忍度依相鄰讀值差中位數的 6 倍調整，下限 1000、上限 10000 ADC counts；完整窗口跨度仍需通過，避免長期漂移被當成穩定。砝碼／歸零維持 2 g 範圍檢查，砝碼訊號至少為雜訊的 10 倍。失敗、取消不覆寫既有係數；設定空載零點成功後需重新砝碼校正。鳥類干擾、視覺失效或 ADC 飽和仍會中止校正。

校正頁顯示等待原因與窗口筆數；20/20 不等於成功，必須看到板端完成。增加 raw_latest（最新原始值）、raw（中位數）、cal_span、rejected_windows、change_pending 供既有重量日誌診斷。未變更鳥類分群演算法、到訪記錄、照片或使用者設定。

此版本需要重新燒錄韌體；只更新網頁不會改變板端取樣。網頁會提示舊版重量韌體。編譯和軟體測試不代表真實荷重元校正精度已驗證。
